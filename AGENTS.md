# Experiment collaboration

- Use a local branch for project work. Open a PR only when the user requests one, against `main` unless directed otherwise. Inspect remote changes without pulling when requested.
- Read [the root README](README.md#course-project-experiments) and the selected benchmark or experiment README and YAML before changing or running it. The shared split uses the exact session IDs in `config/user/single_user.yaml`.
- Keep runnable reference configurations under `benchmarks/` and research comparisons under `experiments/`. Update recommendations in the root README while keeping manifest IDs stable. Add or adjust experiment-specific manifests, results, and model code in that experiment's folder. Leave other experiment folders intact. Keep one generic launcher and Colab notebook. A change to datasets, the training loop, or the benchmark interface belongs in a focused shared change with a description of its effect on existing experiments.
- When resolving merge conflicts in an authorized integration, retain distinct experiment directories and preserve both teams' manifests and results. For conflicts in shared code, preserve current default behavior and implement new behavior as an opt-in when practical. If two changes impose incompatible training or evaluation semantics, keep each experiment reproducible and call out the conflict before choosing a shared default.
- Verify edited manifests with the launcher’s `--plan`. For shared code changes, check the width-48, baseline, and BiGRU launch paths and run the relevant model or data tests. Use separate run directories for different commits or settings.
- Commit manifests, source and concise results. Keep raw recordings, large checkpoints, and full logs in artifact storage. Keep historical reports associated with the commit that produced them.
- Conserve Colab GPU credits. Verify artifacts before releasing the runtime when feasible, and flag idle runtimes during an active interaction.
